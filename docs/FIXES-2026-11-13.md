## 七、追加：桌宠切换角色延迟修复（2026-11-13 18:01）

**现象**：切换角色后桌宠形象有 1~2 秒延迟。

**根因**（`runtime/pet/pet.ps1`）：
1. `Resolve-ImagePath()` 对 `/pet-sprite/*` **每次调用都无条件重新 HTTP 下载** 0.8~1.1MB 的 PNG（无缓存命中判断），PowerShell `Invoke-WebRequest` 单次约 0.4s；
2. 切角色时 `charWatchTimer` 与 `Refresh-Status` **各触发一次 `Update-Image`**，同一张图下载并解码两遍；
3. `Make-Bitmap()` 全尺寸解码大图，且没有位图缓存；切表情（摸头/搓脸/看屏幕）同样每次重下；
4. `Load-Manifest()` 每次切角色都 `Clean-PetCache` 扫目录。

**修复**：
- sprite 已缓存 (`sprite-<角色>-<表情>.png`) 直接复用，不再下载；首次缺失才下载，并改用 `System.Net.WebClient.DownloadFile`（比 `Invoke-WebRequest` 快很多）；
- `Make-Bitmap` 设 `DecodePixelWidth`（按桌宠显示尺寸解码）+ 进程内位图缓存（按路径+mtime）；
- `Update-Image` 增加 key 去重（同一图不再重复渲染），并输出 `image xxx Nms` 日志；
- 头像模式按 `status.character.avatar` 版本号缓存，只在头像变化时下载；
- `Clean-PetCache` 只在启动时执行一次；
- 切角色时记录 `char -> <id>` 日志，便于以后定位类似问题。

**实测**（pet.log，重启桌宠后）：
- 启动首帧：`image sprite-xiaoke-idle.png 129ms`
- 切到 xiaojing：`char -> xiaojing` → `image sprite-xiaojing-idle.png 10ms`
- 切回 xiaoke：`6ms`；再切 xiaojing：`1ms`
- 切换 API 本身 3~4ms；检测延迟取决于 300ms 轮询，整体感知 ≤0.3s（修复前 1~2s）。
