# 虚拟机社交软件通道（基础版）

## 目标

开启后，角色主动找用户时优先：

1. 唤醒 `DSH-Space` 虚拟机
2. 检测虚拟机里有什么社交软件
3. 由 AI 看屏幕选择最合适的软件
4. 先检查有没有找自己的消息
5. 按需回复
6. 把主动消息发到聊天软件
7. 按设置保持运行或存档关闭

**不绑定 QQ**。代码不写死任何具体软件；QQ 只是检测到的一个候选。

## 设置

- `VM 聊天`：主动消息走虚拟机
- `看消息`：唤醒后先检查消息
- `检查间隔`：分钟
- `发完 VM`：自动存档关闭
- `VM 状态`：运行状态和检测到的应用

## 冷启动

1. 虚拟机没运行就唤醒
2. 等桌面就绪
3. 检测可见窗口
4. 没有聊天窗口就按检测到的应用启动（QQ 使用兼容启动参数；其它应用走 gtk-launch）
5. 冷启动后应用可能需要扫码验证，此时返回 `requiresLogin`，不发送任何消息

虚拟机名/路径可用 `DSH_COMPANION_VM`、`DSH_COMPANION_VBOX` 覆盖。

## 检测

通过 SSH 扫描：

- `/usr/share/applications/*.desktop`
- Categories：Network / Chat / InstantMessaging / WebBrowser
- 名称/Exec 里的社交软件关键词
- 当前窗口列表

返回候选列表，交给 AI 选择。

## 读取

- 截图虚拟机桌面
- 宿主机多模态模型读取截图
- AI 返回当前应用、会话、未读消息、输入框/发送位置
- 处理过的消息由后续水位机制避免重复

## 发送

AI 返回输入框归一化坐标后：

- 点击输入框
- 粘贴文字
- 回车
- 发送后不再因为二次识别失败重复回退到聊天页

## 中断与回退

- VM 没启动：按设置自动启动
- 没有可用社交软件：回退插件聊天页
- 没看懂屏幕：不发送，记录错误
- 发送成功：插件聊天页只保留隐藏记录，不重复显示

## 当前边界

- 冷启动后账号可能需要重新扫码验证，插件不会绕过
- 基础版依赖截图和多模态视觉，桌面布局/窗口位置会影响识别
- QQ 等原生应用没有公开消息 API，读取靠看屏幕
- 图片发送还没有接入
- 不同发行版/桌面环境的应用检测可能不同
- 没有登录的软件无法发送
