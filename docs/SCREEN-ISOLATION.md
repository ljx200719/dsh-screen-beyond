# 每角色独立屏幕：已取消

状态：**不做了**（2026-11-12 决定）
适用版本：0.6 及以后

## 决定

所有角色共享同一套环境：

- 同一台 Linux 虚拟机（DSH-Space）
- 同一个安卓模拟器（DSH_Phone）
- 同一个用户 Windows 电脑

切换角色只切换**角色数据**（人设、记忆、日记、地图、位置、钱包、桌宠头像），不切换屏幕、不切换虚拟机、不切换手机。

## 为什么做不到（分发版）

### 1. 插件包不能带运行环境

插件通过 npm/GitHub 分发，体积应保持在几 MB。
独立屏幕需要额外的 Linux 桌面环境，哪怕是 Docker 镜像也要约 0.6～1GB，VirtualBox 镜像更大；不能塞进 npm 包。

用户还必须自己安装并授权：

- Docker Desktop / WSL2，或
- VirtualBox 等虚拟机

这属于系统级安装，不能由插件静默完成，也不能假设每个用户都有。

### 2. 资源成本随角色数量线性增长

一个可用的桌面会话大约需要：

- 200～400MB 内存（轻量 XFCE）
- 更多 CPU 和磁盘
- 每个角色还要独立的 VNC/noVNC 端口

如果按每个角色一台虚拟机：

- 每台约 8GB 内存
- 3 个角色就是 24GB
- 大多数用户机器承受不了

即使改成同一个容器里多用户，仍然要维护多套 X 会话、VNC 端口和进程生命周期，出错面明显变大。

### 3. 跨平台差异大

用户可能用：

- Windows 10/11（家庭版不一定有 Hyper-V）
- macOS
- Linux
- 没有 Docker、没有 WSL2 的机器

同一个“独立桌面”方案很难在所有这些环境里稳定工作。
只支持部分平台，会造成“有的人能用、有的人不能用”的功能分裂。

### 4. 只能做到半个隔离

即使把 Linux 桌面隔离了：

- 安卓手机仍然共用同一个模拟器
- 用户 Windows 电脑仍然是同一台

所以“每个角色完全独立的屏幕环境”本身不成立，只能做局部隔离，收益和复杂度不匹配。

### 5. 维护和测试成本过高

每个角色独立桌面需要额外测试：

- 多用户权限
- 多 X server / 多 VNC 端口
- 桌面进程崩溃恢复
- 端口冲突
- 防火墙和本地安全
- 不同发行版/桌面环境兼容

这些都不是插件核心价值，却会显著拖慢更新。

## 保留的隔离

以下数据仍然按角色独立：

- 人设（meta / persona）
- 记忆与日记
- 地图、位置、访问记录
- 钱包和今日消耗
- 桌宠头像和状态

## 如果以后还要做

只能作为**可选的外部环境适配器**，不能做成插件默认能力：

- 用户自己提供 SSH/VNC 环境
- 插件只负责按角色保存连接信息和切换显示
- 没有环境的用户继续用共享屏幕

当前不排期。
